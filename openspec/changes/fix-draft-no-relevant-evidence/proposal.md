# Proposal: 근거가 질문에 답하지 못하면 답변 초안을 만들지 않는다 (fix-draft-no-relevant-evidence)

## Why

근거 후보가 없으면 답변 초안을 만들지 않고 "근거 없음 — 상담원 작성 필요"를 표시해야 한다(근거: 명세서 v1.5 FR-021 처리 2, AC-021-3). FR-021 처리 2가 가리키는 "근거 없음"은 후보가 비어 있거나 **모든 후보가 기준 미만**인 경우다(근거: 명세서 FR-016 처리 5 "후보가 비어 있거나 모든 후보의 점수가 기준 미만이면 '근거 없음'으로 표시한다. 초안은 만들지 않거나(FR-021 예외) 일반 안내만 쓴다").

지금 코드는 후보가 0개일 때만 초안을 멈춘다(근거: `backend/app/llm/drafts.py` write_reply `if not sources`, 에이전트 설계서 v1.1 12-1 T27 "근거 없음 기준 = 빈 결과, 시작값"). 그런데 검색은 같은 제품 문서 안에서 상위 5개를 늘 가져오므로 제품이 정해진 문의에서는 후보가 0개가 되지 않는다(근거: 명세서 FR-016 처리 1·4, 기술 명세서 v1.4 §4-4 4번 "상위 k = 5").

그 결과 문서에 답이 없는 질문에도 묻지 않은 사양을 늘어놓은 초안이 생긴다. 팀 정답지 GS-065(RAL 도장 색), GS-066(Siemens TIA Portal), GS-067(변압기 소음 dB)는 정답이 "초안 없음, '상담원 작성 필요'"인데, 2026-11-01 main `f823aa3`에서 세 건 모두 FINAL_REPLY DRAFT가 생겼다. 근거 후보는 같은 제품 데이터시트의 무관한 절 5개(점수 0.75~0.78)였고, 검증 에이전트는 GS-066·067만 "질문과 다름"으로 잡고 GS-065는 통과시켰다(근거: eval.gold_set GS-065~067 reference_doc_id "(근거 없음)"·note, 재현 기록 CSV1-004004~004006, 저장소 밖 `B_나송주_시험가이드.md` 3-1).

점수 문턱으로는 가를 수 없다. 무관한 후보의 점수(0.75~0.78)가 정상 문의 CSV1-000004의 1순위 근거 POL-ORDER §1(0.66)보다 높았다(근거: 위 재현 기록, 2026-10-30 추적표 10건 실행 기록, 저장소 밖).

분담표 v3(2026-10-30)는 이 결함을 B(나송주)에게 주고 고침을 "'검증 못 함' 표시"로 적었다. 이 변경은 대신 "초안을 만들지 않음"으로 고친다(결정 2026-11-01 나송주, 조장 확인 필요 → tasks 0.1). 이유: 명세 FR-016 처리 5·FR-021 처리 2·AC-021-3이 이미 정한 동작이고, 정답지 기대와 같고, "근거 없음" 화면(SCR-03-AC-20)과 직접 작성(변경 add-manual-draft)이 이미 있으며, "검증 못 함"은 검증 호출 실패(AC-049-4)의 문구라 뜻이 섞인다(근거: 명세서 AC-049-4, `docs/frontend/screens/SCR-03-ticket-detail.md` SCR-03-AC-20).

## What Changes

- **L4가 "근거로 질문에 답했는가"를 함께 낸다**: 답변 초안 호출(L4)의 구조화 출력에 칸 하나(`coverage`: `ANSWERED` / `PARTIAL` / `NOT_IN_SOURCES`)를 더한다. 칸 이름과 값은 구현 선택이다(근거: 에이전트 설계서 v1.1 4-6 L4 "근거 없는 말은 하지 않는다", 지시문 규칙 1 "묻는 것이 근거에 없으면 팀이 확인한다고 쓴다").
- **답할 근거가 전혀 없으면 초안을 버린다**: `NOT_IN_SOURCES`면 근거 0개와 같은 길로 간다. 초안 없음, 표시 "근거 없음 — 상담원 작성 필요"(근거: FR-016 처리 5, FR-021 처리 2, AC-021-3). `ANSWERED`·`PARTIAL`은 지금과 같다. 일부만 답하면 나머지를 "팀이 확인한다"로 쓰는 지금 동작을 유지한다(근거: 에이전트 설계서 4-6 지시문 규칙 1).
- **복합 문의는 지금 길을 그대로 쓴다**: 초안이 없는 하위 문의는 다른 문의의 메일 상태 목록에 "담당자 확인 중"으로 나온다(근거: 명세서 FR-022 처리 7·예외 3행, AC-022-3, `backend/app/pipeline/graph.py` checking).
- **지시문 새 버전**: L4 지시문 두 개(일반, 부서 회신 있음)에 판단 규칙을 더한 새 파일을 만든다. 부서 회신이 답이면 `NOT_IN_SOURCES`가 아니다(근거: 변경 add-dept-reply C-162 `l4_draft_v3.md`, 에이전트 설계서 12-1 가-6 "부서 회신 숫자는 근거").
- **검색 점수 문턱은 바꾸지 않는다**: T27(근거 없음 기준 = 빈 결과)은 그대로 두고, 그 위에 L4의 판단을 더한다(근거: 위 Why 점수 비교).

## Capabilities

### Modified Capabilities
- `drafts`: 요구사항 "근거와 조회값만으로 답변 초안을 만든다 (FR-021)"의 "근거 없음" 조건에 "근거 후보가 질문에 답하지 못함"을 더한다.

## 범위 밖

- **FR-016 예외 3행 "관련성 낮음" 표시**: 근거 칸에 이 표시를 따로 붙이는 일은 하지 않는다. 화면은 지금의 "근거 없음 — 상담원 작성 필요"로 알린다(근거: 명세서 FR-016 예외 3행, 화면 명세 SCR-03 R-06). 붙일지는 조장 확인(tasks 0.3).
- **고객이 쓴 숫자를 근거 밖 숫자로 잡는 것**(GS-065의 "11 kV", "RAL 7035"): 명세대로의 동작이라 고치지 않는다(근거: 명세서 AC-017-5, 기술 명세서 §3-4 2번 허용 목록).
- **검증 에이전트(L8)의 놓침**(GS-065를 통과시킴): 이 변경으로 무관한 초안이 만들어지지 않으면 같은 경우가 줄어든다. L8 지시문은 고치지 않는다(근거: 명세서 FR-049).
- **에이전트 설계서 T27·4-6 문서 고침**: 주말에는 `docs/`를 고치지 않는다(근거: 분담표 v3 "표 밖 규칙"). 반영할지는 조장 확인(tasks 0.2).

## Impact

- 고치는 파일: `backend/app/llm/drafts.py`(REPLY_SCHEMA, write_reply, 지시문 이름), 새 지시문 `prompts/l4_draft_v4.md`·`prompts/l4_draft_v5.md`(근거: design 결정 1~3). 모두 B 담당 파일이다(근거: 분담표 v3 B "고치는 파일").
- 시험: `backend/tests/acceptance/test_drafts.py`에 시험 추가(근거: CLAUDE.md 규칙 7, design 결정 5). `backend/tests/acceptance/test_run_log.py`의 L4 지시문 이름 기대값이 바뀐다. 이 파일은 A 담당이라 A에게 부탁한다(근거: 분담표 v3 "겹치지 않게 하는 규칙", design Risks).
- API 응답 모양, 화면, 표·열은 바꾸지 않는다(근거: CLAUDE.md 규칙 4, 화면 명세 SCR-03-AC-20이 이미 있음).
