# 화면 명세: SCR-03 티켓 상세

- 연결 요구사항: FR-030 (AC-030-1~5), FR-024 (AC-024-1~4), FR-039 (AC-039-1~4), FR-049 (AC-049-1~6), FR-028 (AC-028-1·2), FR-031 (AC-031-1~6), FR-032 (AC-032-1·2·5), FR-033 (AC-033-1~3·6·7), FR-019 (AC-019-1·3)
- 기준 목업: cs-agent-mockup_v1.42.html `viewTicket`, `judgSection`, `sendColumn`, `draftBlock`, `reviewMarks`, `deptArea`, `similarBlock`, `doSend` (레이아웃 기준선: 머리 카드 + 탭 4개 "고객이 보낸 것 / 시스템이 판단한 것 / 보낼 것 / 이력")
- 화면 정의서: v2 SCR-03M(1순위 최소판), v1 SCR-03(전체판), v2 부록 B
- 사용 API
  - 읽기: `GET /tickets/{id}`, `GET /tickets/{id}/timeline`, `GET /tickets/{id}/runs`, `GET /runs/{run_id}/steps`, `GET /chunks/{chunk_id}`, `GET /sub-tickets/{id}/priority?new_priority=`
  - 쓰기: `PATCH /sub-tickets/{id}`, `POST /tickets/{id}/reprocess`, `PUT /messages/{id}`, `POST /messages/{id}/gloss`, `POST /messages/{id}/verify`, `POST /messages/{id}/send`, `POST /sub-tickets/{id}/priority`, `POST /sub-tickets/{id}/escalate`, `POST /sub-tickets/{id}/dept-reply`, `POST /sub-tickets/{id}/dept-mail`, `POST /tickets/{id}/replies`
  - 아직 없음: `POST /sub-tickets/{id}/drafts`(직접 작성, 변경 add-manual-draft), 상세 응답의 `similar_cases`(변경 add-similar-cases)

## 영역

### 배치 개정 (변경 add-ticket-detail-layout, 2026-11-01)
문의 하나를 처리하는 흐름(읽기 → 파악 → 결정 → 쓰기 → 발송)에 맞춰 한 화면을 다시 짰다. 아래 "탭 ①~④" 이름은 옛 탭의 내용을 가리키며, 지금은 다음 자리에 있다.
- **위**: 머리 카드(번호·상태·고객사·등급, 접수 줄과 "해결 기한 … 초과"), **AI 요약 한 줄 + [원문 보기]**, **"지금 할 일" 띠**(내 차례, 기한 문장, 검토 모드, 진행 단계 6칸). 붉은 경고 띠와 "AI 판단" 칩 줄은 없앴다(같은 정보가 띠·표에 이미 있다).
- **가운데 한 줄**: 왼쪽 "답변 초안"(탭 ③) | 오른쪽 두 탭 — "판단과 근거"(탭 ②, 한 줄씩 표: 유형·긴급도·우선순위·부서·1차 응답/해결 기한·필수 정보, 줄마다 돋보기 [근거 보기]. 고객·제품, 근거 절·조회값, 고장 진단, 이관 후보, 수정, 실행 기록은 [근거 더 보기]에 접힘) / "고객이 보낸 것"(탭 ①, 원문·한국어 번역). P1·안전·설비 정지·복합 문의·상세 검토 문의는 처음부터 "고객이 보낸 것"이 열려 있고, 나머지는 "판단과 근거"가 열려 있다.
- **아래**: 내부 메모, 이력(탭 ④)은 접혀 있고 건수만 보인다. 옛 주소 `?tab=customer|system|history`는 해당 칸을 연다.
- 진행 단계는 서버가 준 `turn`으로 정한다(새 값 없음): 상담원 차례 = 접수·분석·초안 ✓ → 상담원 확인 ● → 발송 → 고객 회신 / 부서 차례 = … 이관 → 부서 회신 ● → 발송 / 고객 차례 = … 발송 ✓ → 고객 회신 ● → 해결.

## 화면 상태

- 로딩: 머리 카드와 탭 자리에 회색 자리.
- 티켓 없음: "티켓을 찾을 수 없습니다 {번호}" + [접수함으로] (404 "티켓을 찾을 수 없음").
- 처리 중: 탭 ①은 보이고 ②·③은 "처리 중" 진행 표시. 2초마다 다시 읽고 끝나면 멈춤.
- 자동 처리 실패: H-04 "자동 처리 실패: {단계} — {사유}" + [다시 처리]. 실패한 문의 칸만 표시, 나머지는 정상.
- 근거 줄 비어 있음: 그 줄만 "없음({사유})"(AC-024-3).
- 정보 요청 필요: C-07 막는 항목 빨강, ③ 정보 요청 탭에 초안, 답변 탭 "막는 정보 요청 중".
- 근거 없음: ③ 답변 탭에 R-06 "근거 없음 — 상담원 작성 필요"와 빈 편집기.
- 고객 회신 대기: 해결 시계 "멈춤", ③ 정보 요청 탭에 보낸 글과 대역.
- 이관됨: 상태 보라, [이관] 꺼짐("이미 이관됨"), 답변 탭에 부서 영역.
- 해결: 보낸 카드 읽기 전용, [고객 회신 입력]은 켜짐.
- 종료: 읽기 전용, 머리에 "종료된 문의입니다".
- 상세 읽기 실패: 이전 값을 흐리게 두고 "불러오지 못함. 새로고침".

화면 정의서 v1·v2의 팝업을 그대로 쓴다. 목업 배치(가운데 대화 창)를 따른다.
